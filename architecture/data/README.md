# Data and Simulator

[Architecture index](../../architecture.md) · [Adapter details](simulator-adapter.md)

| Source | Actual ingestion path | Supported result |
|---|---|---|
| SustainDC simulated studies | Simulation lab → authenticated API → isolated pinned upstream model → immutable owner catalog | Matched constant-setpoint comparison |
| Included SustainDC studies | Precomputed JSON generated by `offline/generate_sustaindc_studies.py` | Same calculations without installing the upstream checkout |
| User CSV observations | Data imports → schema/time/value validation → hash-addressed raw artifact + immutable catalog | Baseline analysis only; source claims unverified |
| Synthetic fixtures | Four generated test scenarios | Workflow/guardrail demonstrations |
| BMS / real facility sensors | Not connected | Future authorized integration |

CSV requires timestamp, interval_hours, cooling_kw, it_kw, max_inlet_c and setpoint_c. Timestamps need UTC offsets and contiguous intervals. Power means interval-average kW; temperature means maximum inlet °C. Missing inlet values block completion rather than being imputed. At most 672 rows / 2 MB are accepted. One imported window must have one constant setting. User confirmation of units is a declaration, not source verification.

`source_kind` remains explicit: simulated, synthetic or measured. The UI labels measured imports **source unverified**. Imported observations cannot be compared as causal counterfactuals. Source bytes are preserved locally under owner/hash-derived names; uploaded names are metadata only and never filesystem paths.

All experiments include scenario/snapshot/zone/horizon/energy boundary and comparison fingerprint. The immutable catalog rejects an existing ID with different content. Default storage is `.local/catalog` and `.local/artifacts`; even Supabase case mode currently needs persistent backend disk for these files. Shared remote artifacts, deletion/retention administration and BMS tag mapping remain unimplemented.
